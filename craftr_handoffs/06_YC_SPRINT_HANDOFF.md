# Craftr — YC Sprint Handoff

## Goal
By the YC deadline, do not build the full Craftr platform.

Prove one thing:

**A person can describe a device and Craftr can produce a working physical prototype.**

## What YC should see
A demo where:
1. user enters an idea
2. Craftr creates ProductSpec
3. components are selected
4. block graph appears
5. enclosure is generated
6. firmware / wiring is generated
7. manufacturing files are produced
8. cut to the real physical product working

## Flagship demo
**MagSafe voice-note device**

Suggested prompt:
> Make me a small MagSafe voice-note device with one button, rechargeable battery, microphone, and phone sync.

Physical proof matters more than polish.

## Second demo
**Plant / irrigation monitor**

Reason:
Two different working devices prove Craftr is a platform rather than a prebuilt recorder workflow.

## Do NOT build before applying
- marketplace
- full payments system
- custom PCB stack
- broad manufacturing network
- hundreds of Blocks
- general-purpose CAD editor
- complex simulation
- mobile app
- perfect UI
- enterprise features

## Sprint sequence
### Days 1–4
- define Block schema
- add ~20–30 Blocks
- create ProductSpec agent
- create compatibility graph

### Days 5–8
- prompt → product architecture
- component selection
- wiring relationships

### Days 9–13
- component placement
- parametric enclosure generation
- STL/STEP export

### Days 14–16
- firmware composition
- automatic compile / repair
- wiring output

### Days 17–19
- outsource fabrication
- assemble
- test
- revise

### Days 20–22
- complete second product
- improve first-build reliability

### Final days
- polish golden path
- get early users
- collect usage numbers
- record founder video
- record physical product demo
- submit

## Application narrative
### Problem
Hardware requires mechanical, electrical, embedded, sourcing, and manufacturing expertise.

### Insight
People do not want to "do CAD." They want a physical object that performs a function.

### Solution
Craftr turns natural-language intent into a manufacturable electronic product.

### Demo
Show working products generated through the same system.

### Vision
**Craftr is a compiler for physical products.**

## Useful proof points before application
Any of these help:
- 10–20 real users tried it
- dozens of product ideas submitted
- several successful generated builds
- users asked to order products
- first paid fabrication orders
- low human intervention per build

## Important mindset
The YC application does not need Craftr to be complete.

The objective is to make the future obvious from a crude but real product.

Better:
"We generated this ugly device and it works."

Than:
"Here is a polished UI showing what we will eventually build."

## Pitch line
**Software lets anyone build software. Craftr does the same for physical products.**
